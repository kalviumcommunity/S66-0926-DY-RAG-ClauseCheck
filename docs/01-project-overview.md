# ClauseCheck — Project Overview

> A retrieval-augmented assistant that lets procurement buyers verify negotiated supplier terms in seconds, with a clause-level citation for every answer.

**Sprint:** Simulated Work, Sprint 2: AI Application Development with RAG
**Track:** AI Application (RAG)

---

## Problem

An enterprise procurement team holds **supplier contracts, pricing agreements, and compliance documents**, but buyers cannot quickly verify negotiated terms because the answers are spread across **hundreds of contracts**.

Today, answering "What are our payment terms with Supplier X?" means finding the right contract, then any amendments, then the right clause. This is slow and error-prone. When a buyer gets it wrong, the cost is real: they accept a wrong invoice price, miss a renewal notice window, or rely on an expired compliance certificate.

## Users

| User | What they need |
|---|---|
| **Procurement buyers** (primary) | Fast, exact answers on price, payment, penalty, renewal, and liability terms before placing orders or approving invoices |
| **Procurement / category managers** | Confidence that terms quoted in negotiations match what is actually signed |
| **Compliance / vendor-risk staff** | Quick checks on NDAs, DPAs, and certificate validity for a given supplier |

## Solution

**ClauseCheck** is a question-answering assistant over the contract repository. A buyer asks a natural-language question, and ClauseCheck:

1. **Scopes retrieval to the named supplier** using metadata filtering.
2. **Retrieves the relevant clauses** using hybrid search (vector similarity + BM25 keyword matching for exact tokens such as "Net 45", "Section 7.2", or SKU codes), then re-ranks them for precision.
3. **Generates a grounded answer** using only the retrieved clauses.
4. **Cites the source**: supplier, document, clause number, and page.
5. **Refuses** with "not found in the contracts" when retrieval is weak, instead of guessing.

**Core question the assistant must answer:**
*"What is the negotiated term (price, payment, penalty, renewal, or liability) with a given supplier, and where exactly in the contracts does it say so?"*

## Scope

**In scope:** multi-format ingestion (PDF, HTML, TXT, DOCX); clause-aware chunking with metadata; hybrid retrieval with re-ranking; grounded answers with citations; refusal handling; conversational follow-ups; a FastAPI backend; a chat UI with streamed answers and visible sources; a document upload endpoint; an evaluation suite; deployment.

**Out of scope (future work):** portfolio-wide aggregation questions (e.g., "which suppliers auto-renew next quarter?"), which need structured extraction at ingestion rather than top-k retrieval; contract drafting or redlining; integration with ERP or invoicing systems.

## Data

| Source | Contents | Licence |
|---|---|---|
| **CUAD** (Atticus Project) | Real commercial contracts (supply, manufacturing, outsourcing, service, maintenance, distributor, hosting), plus expert clause labels used as ground truth | CC BY 4.0 |
| **SEC EDGAR** (EX-10 exhibits) | Additional contracts and **amendments** paired with their original agreements | Public filings |
| **Public vendor DPAs / SLAs** | Real compliance documents | Publicly published; source URLs recorded |
| **Synthetic documents** | Price schedules with volume tiers, compliance and insurance certificates with expiry dates | Generated by a documented script; tagged `is_synthetic` |

## Goals and Success Metrics

| Goal | Metric | Target |
|---|---|---|
| Retrieve the right clause | Recall@5 on the labelled question set | ≥ 0.85 |
| Answer correctly | Answer correctness on the eval set | ≥ 85% |
| Make answers verifiable | Answers whose citation points to the correct clause | ≥ 90% |
| Never invent terms | Correct refusals on unanswerable questions | ≥ 90% |
| Be usable | Median time to first streamed token | < 3 s |
| Ship it | Deployed, documented, reproducible app | By sprint end |

## Tech Stack

Python · PyMuPDF / pdfplumber / BeautifulSoup / python-docx · Gemini API (generation + embeddings; Groq as backup) · ChromaDB or Qdrant · rank_bm25 · cross-encoder re-ranker · FastAPI · Streamlit · SQLite (logging and cache) · GitHub

## Key Assumptions

- The CUAD and EDGAR contracts come from many companies. The project **simulates them as one enterprise's supplier contract repository**.
- Synthetic pricing and compliance documents fill gaps where no public data exists, and are clearly labelled as synthetic.
- Free-tier LLM APIs are acceptable for public and synthetic data. A production deployment on confidential contracts would need a paid or private model.
